## 0. 设计原则（必须遵守）

### 0.1 AI 的定位：引导者（Guide），不是代笔者（Ghostwriter）

**核心原则**：AI 是引导者（Guide），不是代笔者（Ghostwriter）

#### 当前问题
现有 Story Board 的 AI 对话看起来像是"我帮你写 XX 文档"，这是错误的定位。

#### 正确定位
- ❌ AI 直接生成完整内容 → "我帮你写研究背景"
- ✅ AI 引导思考 → "你的研究背景想从哪些角度展开？我帮你梳理框架"
- ❌ AI 产出中间文档 → "这是你的开题报告"
- ✅ 学生思考后产出，AI 帮助提炼 → "根据我们的对话，我帮你整理了这些要点，你看看是否需要调整"

#### 需要在 Story Board 中体现

**1. 对话风格改为引导式：**
- 提问式： "你认为这个研究的创新点在哪里？"
- 启发式： "这个方向可以从 A、B、C 三个角度考虑，你倾向哪个？"
- 框架式： "开题报告通常包含这几个部分，我们先确定哪个部分？"
- 渐进式： 不是一次给答案，而是多轮对话帮助学生自己想清楚

**2. 产物面板要展示"提炼过程"：**
- 不是"AI 生成了 XX 文档"
- 而是"根据对话，系统帮你整理了这些要点"
- 展示：对话要点 → 结构化文档 → 学生修改 → 最终产物
- 产物上标注"学生创作，AI 辅助整理"

**3. AI 使用披露要区分：**
- AI 辅助整理（帮助提炼、格式化）vs AI 生成内容（直接写内容）
- 前者是鼓励的，后者是禁止的

#### 六大阶段必须体现的引导式对话原则

| 阶段 | 错误示范 | 正确示范 |
|------|---------|---------|
| 选题 | "我来帮你写选题说明" | "选题方向有哪些？你有什么初步想法？我帮你梳理框架" |
| 开题 | "我来帮你写开题报告" | "开题报告通常包含5个部分，我们先确定先写哪个部分？" |
| 方案设计 | "我来帮你写技术方案" | "技术方案要考虑哪些因素？硬件/软件/云平台分别有哪些选择？" |
| 实现 | "我来帮你写代码" | "遇到什么编译错误？我帮你分析问题原因" |
| 论文 | "我来帮你写论文" | "第 X 章的结构是否合理？我建议补充这部分内容" |
| 答辩 | "我来帮你写答辩稿" | "答辩PPT的大纲是7个部分，你对哪部分最熟悉？我们先完善它" |

## 1. 整体概述

### 1.0 Welcome Page 欢迎界面（用户首次访问）

Welcome Page 是用户第一次使用系统时的引导页面，快速介绍系统特色和 AI 团队，帮助新用户快速理解系统价值。

**1. 系统核心理念：**
- "毕业设计不是填表，是创造"
- Pipeline 阶段式毕设流程（选题→开题→方案设计→实现→论文→答辩）
- AI 引导式辅助，不是代笔

**2. 双 Agent 团队介绍：**

学生视角：
- "为你配备的 AI 团队"
- 6 个 Agent 头像 + 名称 + 专长（🧭方向顾问、📚文献助手、🏗️架构师、💻代码教练、✍️论文导师、🎤答辩教练）
- "每个阶段，专属 Agent 引导你完成核心工作"

导师视角：
- "为你配备的 AI 团队"
- 4 个 Agent 头像 + 名称 + 职责（📋审核助手、📊进度管家、🔔通知助手、📈统计助手）
- "帮你高效管理学生进度，轻松审核"

**3. 系统核心特色（3-4 个亮点）：**
- AI 引导式对话（不是代笔，是引导你思考）
- AI 使用量化披露（辅助比例、修改率、采纳率）
- 全流程留痕（操作记录、审核记录、辅导记录可追溯）
- 双渠道辅导（系统内 + 即时聊天工具飞书/QQ/微信）

**4. 角色选择：**
- "你是学生还是导师？"
- 两个大按钮：🎓 我是学生 / 👨‍🏫 我是导师
- 选择后进入对应角色的 Dashboard

**设计要求：**
- 现代简洁风格，类似 Notion/Cursor 的欢迎页
- 视觉上有"团队感"（Agent 头像排列、团队协作图示）
- 动画效果（Agent 头像逐个出现、Pipeline 进度条动画）
- 响应式设计，适配桌面和移动端
- 底部有"开始使用"按钮，选择角色后进入主界面

### 1.1 Story Board 目标

Story Board 是一个**高保真静态原型**，不仅是设计参考，更是可以直接演示的产品界面：
- 团队内部汇报 Pipeline 理念
- 向导师/评委展示毕业设计的新范式
- 向领导争取支持（视觉效果好 = 项目说服力强）
- 开发团队理解交互流程和数据结构

### 1.1 高保真原型设计要求

**1. 接近真实产品**：不是线框图，而是完整的视觉设计
**2. 高保真**：每个页面都要有完整的 UI 元素、配色、排版
**3. 科技感 + 年轻化**：暗色主题、渐变、光效、毛玻璃、微动画
**4. 可演示**：页面之间可以流畅切换，有完整的交互流程
**5. 吸引力**：第一眼就要让人眼前一亮

### 1.2 视觉风格（科技感 + 年轻化）

Story Board 需要从三个角度展示完整流程：

**1. 学生视角（主视角）**：
- 展示学生与AI的交互过程
- 展示学生思考、写作、调试的过程
- 展示产品产出和修改记录

**2. 导师视角**（新增）：
- 展示导师审核流程
- 展示反馈意见和回复
- 展示审核通过/驳回记录

**3. 学院管理视角**（新增）：
- 展示毕业设计全流程管理
- 展示进度跟踪和质量监控
- 展示AI使用合规性报告

**4. AI 量化视角**（新增）：
- 展示AI使用时长、轮次、成本
- 展示AI辅助的章节比例
- 展示学生编辑率（Editing Rate）

### 1.3 高保真视觉风格（科技感 + 年轻化）

**1. 主配色**：
- 主色：`#6366f1`（靛蓝）→ `#8b5cf0`（紫）渐变
- 辅色：`#06b6d4`（青）、`#ec4899`（粉）、`#10b981`（绿）

**2. 背景主题**：
- 默认暗色主题：`#0f172a`（深蓝黑）→ `#1e293b`（深蓝灰）渐变
- 可选亮色主题：`#f8fafc`（亮白）→ `#f1f5f9`（浅灰）渐变

**3. 文字颜色**：
- 主文字：`#f8fafc`（亮白）
- 次级文字：`#94a3b8`（中灰）
- 链接/强调：`#8b5cf0`（紫）

**4. 圆角 & 阴影**：
- 卡片圆角：`16px`
- 按钮圆角：`24px`
- 阴影：`0 0 20px rgba(99, 102, 241, 0.3)`（发光效果）

- Pipeline 进度条：流动光效（能量条样式）

- 数字面板：呼吸灯效果

**6. 粒子背景**（Welcome Page）：
- 3D 网格背景
- 飘动的粒子效果
- 半透明毛玻璃卡片

**7. 字体方案**：
- 标题：`Inter` 字体（现代几何感）
- 正文：`Noto Sans SC`（清晰可读）

## 2. 核心架构：双 Agent 团队系统

### 2.1 学生 Agent 团队（Student Agent Team）

**团队成员：**
| Agent | 角色 | 职责 | 对话风格 |
|-------|------|------|---------|
| 🧭 方向顾问 | 选题阶段 | 方向推荐、可行性分析、了解学生兴趣 | 启发式提问、方向对比 |
| 📚 文献助手 | 开题阶段 | 文献推荐、框架梳理、了解学生研究方向 | 文献引导、结构建议 |
| 🏗️ 架构师 | 方案设计 | 技术选型、架构设计、了解学生技术栈 | 方案对比、架构建议 |
| 💻 代码教练 | 实现阶段 | 代码调试、测试建议、了解学生代码风格 | 错误提示、调试引导 |
| ✍️ 论文导师 | 论文阶段 | 结构建议、格式检查、了解学生写作风格 | 逻辑检查、语言润色 |
| 🎤 答辩教练 | 答辩阶段 | PPT 制作、模拟问答、了解学生表达习惯 | 问答模拟、演讲建议 |

**团队特点：**
- 团队成员共享学生上下文（专业、进度、偏好、历史产物）
- 每个 Agent 只在自己阶段出现，但知道其他阶段的成果
- 学生视角：看到"我的 Agent 团队"，可以查看各 Agent 的贡献

### 2.2 导师 Agent 团队（Advisor Agent Team）

**团队成员：**
| Agent | 角色 | 职责 |
|-------|------|------|
| 📋 审核助手 | 审核支持 | 整理待审核内容、生成审核建议、标注 AI 使用痕迹 |
| 📊 进度管家 | 进度监控 | 监控所指导学生进度、预警滞后学生 |
| 🔔 通知助手 | 消息推送 | 通过飞书/微信推送重要提醒、汇总每日待办 |
| 📈 统计助手 | 数据分析 | 生成所指导学生分析报告、AI 使用统计 |

**团队特点：**
- 导师视角：看到"我的 Agent 团队"，可以查看各 Agent 的工作记录
- 导师 Agent 与学生 Agent 协作（如：审核助手接收学生提交的产物，整理后给导师审核）
- 通知助手跨平台工作（飞书/QQ/微信）

### 2.3 Agent 协作流程

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│              │     │              │     │              │
│  学生 Agent  │────▶│  学生提交产物 │────▶│  导师 Agent  │
│              │     │              │     │              │
└──────────────┘     └──────────────┘     └──────────────┘
                                      │
                                      ▼
                              ┌──────────────┐
                              │              │
                              │   导师审核   │
                              │              │
                              └──────────────┘
```

**协作节点说明：**

1. **阶段completed时**：学生 Agent 整理本阶段成果，生成提交清单
2. **提交产物时**：学生 Agent 自动标注 AI 使用痕迹（Agent名称、辅助内容、学生编辑率）
3. **导师接收时**：导师 Agent 自动整理待审核列表、生成审核建议
4. **审核反馈时**：导师通过双渠道反馈（系统内 + 即时聊天），自动同步留痕

      ▶ 工作模式：
        - AP模式：作为热点，其他设备连接
        - STA模式：作为客户端，连接路由器

        - WEP：有线等效加密（已淘汰）

      ## 导师常见问题

      2. **开发简单**：ESP32有丰富的开发资源和社区支持，
         ESP-IDF和Arduino框架都很容易上手。
      
      3. **功耗低**：ESP32支持多种低功耗模式，
         适合电池供电的应用场景。
      
      4. **成本相当**：ESP32-WROOM-32E约¥35，
         STM32F103C8T6约¥8，但STM32需要额外的成本购买Wi-Fi模块。
