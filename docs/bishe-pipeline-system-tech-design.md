## 1. 系统概述

### 1.1 核心理念

**毕业设计不是填表，是创造。**

将毕业设计拆解为若干个独立的"阶段"（Pipeline Stage），每个阶段是一个独立的工作空间，师生在 AI 辅助下以**对话式交互**完成核心工作，产出结构化的**中间文件**。最后通过一个轻量级的知网注入插件，将中间文件自动填入知网系统完成合规交差。

### 1.2 架构总览

```
┌─────────────────────────────────────────────────────────────────┐
│                    Pipeline 毕业设计系统                           │
│                                                                 │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐      ┌─────────┐        │
│  │ 选题阶段 │→│ 开题阶段 │→│ 方案设计 │→...→│ 答辩阶段 │        │
│  └────┬────┘  └────┬────┘  └────┬────┘      └────┬────┘        │
│       │            │            │                │             │
│       ▼            ▼            ▼                ▼             │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │                    中间文件仓库                           │    │
│  │  (结构化 JSON / Markdown / 代码 / 图片 / 数据)            │    │
│  └────────────────────────┬────────────────────────────────┘    │
│                           │                                     │
│                           ▼                                     │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │             知网注入插件 (Chrome Extension)               │    │
│  │  - 读取中间文件                                          │    │
│  │  - 用户登录知网后自动填充对应表单                          │    │
│  │  - 用户确认后提交（批量提交可选）                          │    │
│  └─────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 系统分层

| 层 | 组件 | 职责 |
|----|------|------|
| **体验层** | Pipeline Web App | 对话式交互界面、产物面板、导师协作 |
| **业务层** | 阶段引擎 | 管理每个阶段的流转、产物生成、审核 |
| **AI 层** | AI 服务 | 对话引导、产物整理、代码辅助、检查 |
| **数据层** | 中间文件仓库 | 存储结构化的阶段产物 |
| **合规层** | 知网注入插件 | 读取中间文件，自动填入知网表单 |

## 2. 核心数据模型

### 2.1 中间文件格式（JSON Schema）

每个阶段产出一个标准化的中间文件，定义如下：

```json
{
  "schema": "pipeline-intermediate-file-v1",
  "stage": "proposal",               // 阶段标识
  "student": { "id": "", "name": "" },
  "advisor": { "id": "", "name": "" },
  "title": "基于ESP32的智能垃圾桶设计",
  "status": "draft",                 // draft | review | approved | rejected
  "version": 3,
  "generatedAt": "2026-05-10T12:00:00Z",
  "sections": [
    {
      "id": "research_background",
      "label": "研究背景",
      "content": "随着城市化进程...",
      "aiAssisted": true,            // AI 辅助标识
      "aiPrompt": "请生成研究背景",    // AI 提示词（用于披露）
      "humanEditRate": 0.7           // 人工修改比例
    }
  ],
  "aiDisclosure": {
    "modelsUsed": ["deepseek-v3"],
    "aiAssistedSections": ["research_background"],
    "totalAiRatio": 0.3
  },
  "advisorComments": [
    { "from": "导师姓名", "content": "背景部分需要补充数据", "at": "..." }
  ]
}
```

### 2.2 Pipeline 状态机

```
DRAFT → REVIEW → APPROVED → EXPORTED
                  ↓
              REJECTED → DRAFT (修订)
```

每个阶段的流转：
1. **DRAFT**: 学生与 AI 对话，生成产物草稿
2. **REVIEW**: 学生提交给导师审核
3. **APPROVED/REJECTED**: 导师审核通过/退回修改
4. **EXPORTED**: 导出为中间文件，可被知网插件读取

## 3. 阶段设计

### 3.1 通用阶段组件

每个阶段包含三个核心组件：

```
┌────────────── AI 对话区 ───────────────┐
│ - 流式对话 (SSE/WebSocket)              │
│ - 上下文感知 (知道当前阶段和之前产物)      │
│ - 建议引导 (不替学生决策)                │
└──────────────────────────────────────────┘

┌────────────── 产物面板 ─────────────────┐
│ - 对话内容自动提取为结构化文档            │
│ - 实时更新 (每句对话都可能触发更新)        │
│ - Markdown 渲染 + 内联编辑               │
└──────────────────────────────────────────┘

┌────────────── 导师反馈区 ───────────────┐
│ - 差异对比 (只看改动部分)                │
│ - 轻量回复 (飞书/邮件/微信推送)           │
│ - 审核记录 (完整可追溯)                  │
└──────────────────────────────────────────┘
```

### 3.2 阶段定义（以工科为例）

#### Stage 1: 选题

| 属性 | 值 |
|------|----|
| 时长 | 1-2 周 |
| AI 角色 | 方向推荐 + 可行性分析 |
| 学生产出 | 选题说明、技术可行性评估 |
| 导师参与 | 确认选题方向 |
| 中间文件 | `topic-report.json` |

**对话开场白示例：**
```
系统: 欢迎来到选题阶段！
      你的专业是电子信息工程，有什么感兴趣的方向吗？
      
      我建议从这几个方向考虑：
      🔹 嵌入式系统（智能硬件、IoT）
      🔹 计算机视觉（图像识别、目标检测）
      🔹 信号处理（音频分析、滤波算法）
      
      你倾向哪个方向？
```

#### Stage 2: 开题报告

| 属性 | 值 |
|------|----|
| 时长 | 2-3 周 |
| AI 角色 | 文献推荐 + 框架梳理 |
| 学生产出 | 开题报告（研究背景、文献综述、研究方案） |
| 导师参与 | 审核研究方向和方案 |
| 中间文件 | `proposal.json` |

#### Stage 3: 方案设计

| 属性 | 值 |
|------|----|
| 时长 | 2-3 周 |
| AI 角色 | 技术选型对比、架构建议、实验方案设计 |
| 学生产出 | 方案设计文档、技术选型对比表、系统架构图 |
| 导师参与 | 审核技术方案 |
| 中间文件 | `design-doc.json` |

#### Stage 4: 实现

| 属性 | 值 |
|------|----|
| 时长 | 4-6 周 |
| AI 角色 | 代码调试、错误提示、测试建议 |
| 学生产出 | 代码、测试报告、实验数据 |
| 导师参与 | 检查进度，代码审查 |
| 中间文件 | `code-archive.zip`, `test-report.json` |

#### Stage 5: 论文

| 属性 | 值 |
|------|----|
| 时长 | 4-6 周 |
| AI 角色 | 结构建议、格式检查、语言润色（需披露） |
| 学生产出 | 论文初稿、定稿 |
| 导师参与 | 审核论文 |
| 中间文件 | `thesis-draft.json`, `thesis-final.json` |

#### Stage 6: 答辩

| 属性 | 值 |
|------|----|
| 时长 | 1 周 |
| AI 角色 | PPT 模板、模拟问答 |
| 学生产出 | 答辩 PPT、演示材料 |
| 导师参与 | 模拟答辩 |
| 中间文件 | `defense-ppt.pptx`, `qa-prep.md` |

## 4. AI 交互设计

### 4.1 对话引导策略

每个阶段采用**渐进式引导**，不是一次展示所有内容：

```
第1轮: "我们先确定最核心的问题"
      ↓
第2轮: "基于你的回答，我建议..."
      ↓
第3轮: "好的，接下来我们细化..."
      ↓
第4轮: "这是目前产出的文档，你看哪里需要调整？"
```

### 4.2 AI 辅助原则

```
✅ 可以做:
   - 拆解问题，提供思路方向
   - 推荐技术方案，对比优劣
   - 检查逻辑漏洞，指出遗漏
   - 自动整理对话成文档
   - 代码调试提示

❌ 不可以做:
   - 替学生写核心内容
   - 替学生做设计决策
   - 生成原始数据或实验结果
   - 隐藏 AI 使用痕迹
```

### 4.3 AI 使用披露

系统自动生成 AI 使用报告，包含：
- 使用的 AI 模型列表（名称、版本）
- AI 辅助的具体部分和内容
- 学生的修改和审校情况
- AI 使用比例（供学校参考）

## 5. 知网注入插件设计

### 5.1 插件职责

```
插件只做一件事：
  读取本地中间文件 → 映射到知网表单 → 自动填充 → 用户确认后提交

不做的事：
  ❌ 不提取知网页面数据
  ❌ 不绕过身份验证
  ❌ 不爬取知网内容
  ❌ 不自动提交（用户确认后提交）
```

### 5.2 插件架构

```
┌─────────────────────────────────────────┐
│  知网注入插件 (Chrome Extension V3)      │
│                                         │
│  ┌─────────────┐  ┌───────────────────┐ │
│  │ 中间文件读取器 │  │ 表单映射引擎       │ │
│  │ (读取本地文件)  │  │ (中间文件→知网字段)│ │
│  └──────┬──────┘  └────────┬──────────┘ │
│         │                   │            │
│         ▼                   ▼            │
│  ┌───────────────────────────────────┐   │
│  │        知网表单填充器               │   │
│  │  (模拟人工操作，非绕过)              │   │
│  └──────────────┬────────────────────┘   │
│                 │                        │
│                 ▼                        │
│  ┌───────────────────────────────────┐   │
│  │      批量提交（用户确认后）          │   │
│  │  - 串行处理                        │   │
│  │  - 每步延迟 1.5-3 秒               │   │
│  │  - 用户手动触发                     │   │
│  └───────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

### 5.3 合规保障

| 措施 | 说明 |
|------|------|
| 用户登录后才工作 | 不碰身份验证 |
| 仅填充已登录的表单 | 不爬取、不导出知网数据 |
| 用户确认后提交 | 不自动提交 |
| 操作节奏模拟人工 | 串行处理 + 随机延迟 |
| 用户协议明确 | 第三方工具声明、免责声明 |

## 6. 技术栈建议

### 6.1 Pipeline Web App

| 层 | 技术选型 | 说明 |
|----|---------|------|
| 前端框架 | React + TypeScript | 生态成熟，组件化 |
| 聊天 UI | 自定义组件 | 类似 Claude/Cursor 的对话界面 |
| 产物编辑 | Monaco Editor / TipTap | 代码编辑 + 富文本 |
| 状态管理 | Zustand | 轻量级状态管理 |
| 流式通信 | Server-Sent Events | AI 响应流式输出 |
| 存储 | PostgreSQL + S3 | 结构化数据 + 文件存储 |

### 6.2 AI 集成

| 组件 | 选型 | 说明 |
|------|------|------|
| 对话模型 | DeepSeek V3 / 通义千问 | 国内合规，性价比高 |
| 代码辅助 | DeepSeek Coder | 代码生成与调试 |
| 文档提取 | LLM + 模板引擎 | 对话→结构化文档 |
| 合规检查 | 本地规则引擎 | AI 使用检测，零外部调用 |

### 6.3 知网插件

| 组件 | 选型 |
|------|------|
| 框架 | Chrome Extension Manifest V3 |
| 文件读取 | File System Access API / 用户选择文件 |
| 表单注入 | Content Script + DOM 操作 |
| 存储 | chrome.storage.local |

## 7. 实施路线图

### Phase 1: MVP（2-3 个月）

**目标**: 一个可用的工科毕设 Pipeline，支持完整的开题→论文流程

- [ ] Pipeline Web App 基础框架
- [ ] 选题 + 开题 + 方案设计 + 论文 四个阶段
- [ ] AI 对话引导（DeepSeek 接入）
- [ ] 对话→文档自动提取
- [ ] 导师审核功能（基础版）
- [ ] 中间文件导出
- [ ] 知网注入插件 v1（单篇填充）

### Phase 2: 打磨（1-2 个月）

**目标**: 优化体验，覆盖更多场景

- [ ] 代码调试模块
- [ ] 答辩 PPT 生成
- [ ] 导师轻量互动（飞书/微信推送）
- [ ] 批量提交插件
- [ ] AI 使用披露报告
- [ ] 文科适配（文献分析、数据可视化）

### Phase 3: 推广（持续）

**目标**: 扩大用户基础，建立生态

- [ ] 开源发布
- [ ] 更多专业适配模板
- [ ] 高校合作（私有化部署）
- [ ] Pipeline 市场（师生共享模板）

## 8. 数据安全与合规

| 要求 | 措施 |
|------|------|
| 数据最小化 | 仅传输必要的对话内容到 AI 服务 |
| 国内模型 | 使用 DeepSeek/通义等国内备案模型 |
| 用户同意 | 首次使用 AI 时弹窗获取单独同意 |
| 数据加密 | 传输加密 (HTTPS) + 存储加密 (AES-256) |
| 删除权 | 用户可随时删除所有数据 |
| AI 披露 | 自动生成 AI 使用报告 |
| 涉密项目 | 检测涉密关键词，拒绝处理 |

## 9. 附录

### 9.1 与知网的关系

```
Pipeline 系统         中间文件          知网注入插件         知网
  (独立)          ──→   (标准格式)  ──→   (Chrome)    ──→   (交差)
                                                             
 无依赖              无依赖            用户登录后工作          最终目标
 不受知网控制        可版本管理         只写不读              合规交差
```

### 9.2 关键决策记录

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 插件是否提交 | 自动/手动 | 用户确认后提交 | 合规优先，效率其次 |
| AI 模型 | 海外/国内 | 国内备案模型 | 数据不出境 |
| 中间文件格式 | 专有/开放 | 开放 JSON Schema | 可对接任何系统 |
| 导师交互 | 系统内/轻量 | 飞书/邮件推送 | 降低导师使用门槛 |
| 商业化 | 付费/开源 | 开源 + 托管 | 降低推广阻力 |
